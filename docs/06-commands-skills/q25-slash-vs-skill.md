# Q25. カスタムスラッシュコマンドとスキルの違いは「管理場所」だけ？

📚 [トップ索引](../../README.md) ｜ [カテゴリ索引: コマンド・スキル](README.md)

---

> **メタ**: 最終確認日 2026/4/16 ｜ 根拠 https://docs.devin.ai/product-guides/skills / https://docs.devin.ai/product-guides/slash-commands ｜ 推定なし

### 結論: **いいえ、それだけではない**。管理場所の違い（Devin管理 vs repo管理）は**表面的な違いの1つ**で、そこから派生する**本質的な違いが5〜6個**ある

### 核心: 2つは別レイヤーの機能

- **スラッシュコマンド** = 「ユーザが**入力するメッセージ**のショートカット」（チャット欄に展開される）
- **スキル** = 「Devinが**従う行動指示**」（システム指示として注入される）

```
ユーザ入力 ─[スラッシュコマンド]→ 展開されたメッセージ → Devin
                                                          ↑
                                           [スキル] ──── 自動/明示的に発動
                                           (システム指示として注入)
```

**Slashコマンドは"入力補助"**、**Skillは"実行指示"** で、**レイヤーが違う**。

### 本質的な違い一覧

| 観点 | **カスタムスラッシュコマンド** | **スキル（SKILL.md）** |
|---|---|---|
| **保存場所** | Devin側（組織設定） | repo内 `.agents/skills/`等 |
| **実体** | プロンプトテンプレート（テキスト） | 手順書（YAMLフロントマター+Markdown+動的処理） |
| **発火方法** | **常に明示的**（`/command`と打つ） | **自動 or 明示的**（description/triggersマッチで自動、または`@skills:name`） |
| **ユーザ介入** | 展開後に**編集してから送信**できる | 発動後は**そのまま実行**される |
| **Devinへの伝わり方** | ユーザの**メッセージとして届く** | **システム指示として注入**される |
| **動的コンテンツ** | なし（静的テキスト） | **あり**（`$ARGUMENTS`, `` !`command` ``でシェル実行結果埋込） |
| **ツール制限** | なし | **`allowed-tools`で制限可**（例: 読み取り専用skill） |
| **スコープ** | **組織全体**（全repoで使える） | **repo単位**（そのrepoでのみ有効） |
| **ガバナンス** | 組織管理者が直接編集 | **GitのPRレビュー**を経て変更 |
| **バージョン管理** | 管理画面の編集履歴 | **git履歴**（誰がいつ変更したか追える） |
| **他ツール互換性** | Devin固有 | **Agent Skills標準**（Claude Code等と互換） |
| **自動提案機能** | なし | **Skill Suggestions**（Devinが自動提案＋PR化） |

### 「管理場所の違いだけ」と言えない具体例

**違い1: トリガーが自動 vs 手動**
- Skill: descriptionが「テスト実行時」なら、「テスト走らせて」と言うだけで**自動発動**
- Slashコマンド: ユーザが明示的に `/test` と打たないと発動しない

**違い2: 動的コンテンツの有無**
- Skillは実行時にシェル実行結果を埋込可能:
  ```markdown
  - Branch: !`git branch --show-current`
  ```
- Slashコマンドは**静的テンプレート**のみ

**違い3: 編集のタイミング**
- Slashコマンド: 展開されたテンプレートを**ユーザが編集してから送信**
- Skill: 発動したら編集の余地なし、**そのままDevinが実行**

**違い4: スコープとガバナンス**
- Slashコマンド: 組織全体、管理者UIで編集 → **中央集権型**
- Skill: repo単位、PRレビュー経由 → **分散ガバナンス型**

**違い5: ツール制限**
- Skillは `allowed-tools`で Devinを読み取り専用等に制限可
- Slashコマンドにはこの機能はない

### 使い分けの判断フロー

```
Q1: ユーザが毎回明示的に呼ぶ？
  Yes → スラッシュコマンド
  No → Skill

Q2: 組織全体で使う？repo固有？
  組織全体 → スラッシュコマンド
  repo固有 → Skill

Q3: 動的なコマンド実行結果を埋めたい？
  Yes → Skillしかできない

Q4: Devinの行動をツール単位で制限したい？
  Yes → Skill

Q5: バージョン管理・レビューを厳密にしたい？
  Yes → Skill（git経由）

Q6: 毎回プロンプトを編集してから送りたい？
  Yes → スラッシュコマンド
```

### 典型的な使い分け例

| やりたいこと | どちら？ | 理由 |
|---|---|---|
| 「新機能追加」の定型プロンプトを組織で共有 | **スラッシュコマンド** | 毎回編集前提、組織横断 |
| このrepoのデプロイ手順を固定化 | **Skill** | repo固有、同じ手順を再現 |
| 「セキュリティレビュー」観点チェックリスト | **スラッシュコマンド** | 全repoで使う、編集して投げる |
| アプリのテスト起動手順 | **Skill** | repo固有、自動発動したい |
| 「調査してレポートして」テンプレ | **スラッシュコマンド** | タスクごとに内容変化 |
| 読み取り専用でコードベース調査 | **Skill** | `allowed-tools`で制限可 |
| CI失敗を直すときの定型手順 | **Skill** | 自動発動、repo環境依存 |

### まとめ

- 「管理場所の違いだけ」ではない。管理場所は**表面の1つ**
- 本質は「**入力補助**」vs「**実行指示**」という**レイヤーの違い**
- 根本的な違い6つ:
  1. 発火が**手動のみ** vs **自動可**
  2. 展開後に**編集可** vs **即実行**
  3. **静的テンプレート** vs **動的処理**
  4. **組織スコープ** vs **repoスコープ**
  5. **管理者UI** vs **PRレビュー**（ガバナンス）
  6. **Devin固有** vs **業界標準**（他ツール互換）
- 用途で使い分ける: 「毎回編集して送る定型プロンプト」=スラッシュコマンド、「再現性が欲しい・自動発動」=スキル

**核心**: **Skill = Devinの振る舞いを改善、Playbook = ユーザ起動の手順、Knowledge = 事実情報**。3 層の役割を混ぜないのがコツ。
