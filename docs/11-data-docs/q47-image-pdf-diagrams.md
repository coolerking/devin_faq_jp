# Q47. DevinはExcel上の図、Word・PDF上の図をどのくらい理解できる？

📚 [トップ索引](../../README.md) ｜ [カテゴリ索引: データ入出力・ドキュメント理解](README.md)

---

> **メタ**: 最終確認日 2026/4/16 ｜ 根拠 https://docs.devin.ai/ ｜ 推定あり

### 結論: **(1) テキスト・表・セル内数値はほぼ完全に読める**。**(2) Vision（Claude Sonnet 4.5）で画像として認識できる図は「概要・構造・文字・色・配置」まで理解可**。**(3) ただしExcelのネイティブグラフ・SmartArt・ベクター図は"画像化してから"渡す必要があり**、**素のまま渡すと形状データは失われやすい**。**(4) 複雑な技術図・細かい数値ラベル・日本語の手書き風は精度低下**

### まず前提: Devinが「図を見る」2つの経路

| 経路 | 内容 | 精度 |
|---|---|---|
| **A. ファイル→テキスト抽出** | Word/Excel/PDFをパース、テキスト・数値・構造を取り出す | **高**（文字）、低（図） |
| **B. 画像→Vision認識** | 図を画像化してClaude Visionに渡す | **中〜高**（図全体の構造） |

→ **「素のExcel/Word/PDFをそのまま渡す」と経路Aのみ動作、図情報は部分的にしか拾えない**ことが重要。

### ファイル形式別の理解度マトリクス

### Excel（.xlsx）

| 要素 | Devinの理解度 | 備考 |
|---|---|---|
| **セル値・数式** | ⭐⭐⭐⭐⭐ 完全 | `openpyxl` / `pandas` で読み取り |
| **書式（色・フォント）** | ⭐⭐⭐⭐ 高 | xlsx内XMLにメタデータ |
| **シート構成** | ⭐⭐⭐⭐⭐ 完全 | シート名、リンク、範囲 |
| **ネイティブグラフ（棒・円・折れ線）** | ⭐⭐ 低 | 構造データは読めるが**画像として見えない** |
| **挿入画像（PNG/JPG）** | ⭐⭐⭐ 中 | 抽出して Visionで認識可 |
| **SmartArt（組織図等）** | ⭐⭐ 低 | XML要素としては拾えるが、**視覚的理解は弱い** |
| **図形（矢印・吹き出し）** | ⭐⭐ 低 | XML上の位置・色情報のみ |
| **セル内オブジェクト** | ⭐ 最低 | 埋込OLEは扱いにくい |
| **ピボットテーブル** | ⭐⭐⭐⭐ 高 | 計算結果とソース構造が取れる |
| **マクロ（VBA）** | ⭐⭐⭐⭐ 高 | コードとして読める |

### Word（.docx）

| 要素 | Devinの理解度 | 備考 |
|---|---|---|
| **本文テキスト** | ⭐⭐⭐⭐⭐ 完全 | `python-docx`で段落・スタイル・箇条書きまで |
| **見出し階層** | ⭐⭐⭐⭐⭐ 完全 | Heading 1/2/3の構造 |
| **表** | ⭐⭐⭐⭐⭐ 完全 | セル単位で取れる |
| **挿入画像（PNG/JPG）** | ⭐⭐⭐ 中 | 抽出→Vision認識 |
| **ネイティブ図形（四角・矢印）** | ⭐⭐ 低 | Drawing XML要素として存在するが**構造再現は弱い** |
| **SmartArt** | ⭐⭐ 低 | 要素は拾えるが**視覚的理解は苦手** |
| **数式（OfficeMath/LaTeX）** | ⭐⭐⭐⭐ 高 | 数式としてパース可 |
| **コメント・変更履歴** | ⭐⭐⭐⭐ 高 | XMLから取得 |
| **ヘッダ・フッタ** | ⭐⭐⭐⭐ 高 | 可 |
| **埋込Excel/PowerPoint** | ⭐⭐ 低 | 展開して個別処理が必要 |

### PDF

| 要素 | Devinの理解度 | 備考 |
|---|---|---|
| **テキスト層あり（.pdf from Word等）** | ⭐⭐⭐⭐⭐ 完全 | `pypdf` / `pdfplumber` / `pymupdf`で抽出 |
| **テキスト層なし（スキャンPDF）** | ⭐⭐⭐ 中 | OCR（Tesseract等）必要、日本語可 |
| **表（テキスト層あり）** | ⭐⭐⭐⭐ 高 | `camelot` / `tabula` / `pdfplumber.extract_tables` |
| **ベクター図（CAD/ドロー）** | ⭐⭐ 低 | ラスタライズ→Vision必要 |
| **ラスター画像埋込** | ⭐⭐⭐ 中 | 抽出→Vision認識 |
| **注釈・ハイライト** | ⭐⭐⭐ 中 | ライブラリで取得可 |
| **フォーム** | ⭐⭐⭐ 中 | フィールド値取得可 |
| **日本語フォント埋込PDF** | ⭐⭐⭐⭐ 高 | pymupdfで安定 |
| **パスワード保護PDF** | ⭐⭐ 低 | パスワード渡せば可 |

### Vision認識（画像として見える場合）の理解度

**画像化して渡せば**以下のレベルまで理解する（Claude Sonnet 4.5のVision能力）:

### ✅ 得意

| 内容 | レベル |
|---|---|
| **フローチャート** | 主要ノード・矢印・判断分岐を文章化可能 |
| **アーキテクチャ図** | コンポーネント名・接続関係・階層を把握 |
| **シーケンス図** | アクター間のやり取り順序を再構築可 |
| **ER図** | エンティティ・属性・関係を抽出 |
| **グラフ（棒/折れ線/円）** | 軸ラベル・凡例・傾向の説明、**細かい数値は目分量** |
| **ガントチャート** | タスク・期間・依存関係を把握 |
| **UI モックアップ** | 画面要素の配置・階層を説明 |
| **ホワイトボード写真** | 手書き図でも構造は理解可、日本語手書きは精度低下 |
| **スクリーンショット** | UIの状態、エラーメッセージの読み取り可 |
| **写真・イラスト** | 一般物体認識は高精度 |

### ⚠️ 苦手

| 内容 | 問題 |
|---|---|
| **超高密度回路図** | 記号密度が高くて誤認識 |
| **CAD図面の寸法** | ミリ単位の数字は読み違えやすい |
| **微細なラベル** | 5px以下のフォントは読めない |
| **日本語手書き** | 英語より精度低 |
| **重なり合った多層図** | レイヤ分離が難しい |
| **数式+注釈が密集** | 読み違いリスク |
| **同色系の細い線の多重フロー** | 線の追跡ミス |
| **スキャン劣化画像** | ノイズで文字化け |

### 実際の処理パターン

### パターン1: Excelのグラフをそのまま理解させたい
```
❌ NG: .xlsx をアップロードして「グラフを説明して」
      → セル値は読めるがグラフ画像として見えない

⭐ 推奨:
1. Excelでグラフを選択 → 「図として保存」(PNG)
2. PNGをチャットに添付 → Devinが Vision で解釈
3. または Devin にお願いして:
   - openpyxlで元データ取得
   - matplotlib等で再描画
   - その画像を読む
```

### パターン2: Word内のフローチャート
```
❌ NG: .docx アップロードで「3ページ目のフローチャートを説明して」
      → テキストは読めるが図は部分的にしか理解しない

⭐ 推奨:
1. Word上で図を選択→コピー→画像貼付（PNG化）
2. 該当ページのみPNGエクスポート
3. PDFに印刷してからPDFページを画像化
4. チャットに画像として添付
```

### パターン3: PDFの図を理解させたい
```
⭐ 推奨:
- Devinに `pdf2image` でページを画像化させる
- 図のある範囲をクロップして Vision に渡す

例:
from pdf2image import convert_from_path
images = convert_from_path("doc.pdf", dpi=300)
images[5].save("page_6.png")
# この page_6.png をチャットに提示
```

### パターン4: スキャンされた手書きメモ
```
⭐ 推奨（OCR併用）:
1. 画像を tesseract でOCR（日本語対応: `-l jpn`）
2. テキスト化された内容＋元画像の両方をDevinに
3. Visionでレイアウト理解＋OCRテキストで精度補強
```

### Devinに図を渡す際のベストプラクティス

### 🎯 解像度・サイズ
- **最低 1024px以上の幅**を推奨
- **DPI 200以上**（スキャンPDF・写真）
- 細かいラベルは **拡大したクロップを別途追加**で精度上がる

### 🎯 フォーマット
- **PNG**（ロスレス・推奨）
- JPG（写真OK、文字はややぼやける）
- WebP（対応、ただしPNG優先）
- SVG（直接解釈は限定的、PNG変換が無難）

### 🎯 補助情報の提供
図単独ではなく、**コンテキスト**を文章で添える:
```
「これは本アプリの認証フロー図です。
 OAuth2.0を使い、ユーザ→フロント→BFF→IdPの順で認証します。
 赤矢印がトークン要求、緑矢印がトークン返却です。
 この図の問題点を指摘してください。」
```
→ Visionだけに頼らず**文脈補強**で精度大幅向上。

### 🎯 複雑な図の分割
- **全体図 + 拡大パーツ画像を複数添付**
- 「まず全体を見て、次に赤枠内を詳細に」と段階的に

### 🎯 テキスト版との併用
- **本当に重要な図はテキストでも説明する**
  - フローチャート → Mermaid
  - 表 → Markdown表
  - アーキテクチャ → 箇条書きで構成要素・関係を列挙
- Devinに両方渡せば**クロスチェック可能**

### よくあるハマりどころ

### ハマり1: Excelをzipと思って直接展開しても、グラフは再現できない
xlsxはzipなので中身は見える:
```bash
unzip -l sample.xlsx
# → xl/charts/chart1.xml が見える
```
→ **ただしこれはChart要素のXML定義**、画像ではない。再レンダリングが必要。

### ハマり2: PDFのテキスト抽出で文字化け
- フォント埋込なし、または独自コードマップのPDFで発生
- `pymupdf`で改善することが多い
- 最終手段: OCRで読み直す

### ハマり3: Word内の画像を"見ない"
- `.docx`をunzipして`word/media/`配下にPNG/JPGがあるのを取り出せば、Vision可能
- Devinに「word/mediaの画像を全部Vision認識して」と頼める

### ハマり4: PDFの図の座標は取れるが中身が分からない
- 図の**バウンディングボックスは取れる**が、図の内容は画像化しないと分からない
- 該当座標をクロップ→画像化→Vision

### ハマり5: SmartArtはXML上は要素として存在
- 組織図やプロセス図などのSmartArtは xmlで`dgm`ノードで定義
- **構造は取れるが、Devinに絵として見せたいなら**PNG エクスポート必要

### 精度を上げるテクニック集

### テク1: 「図の説明→構造化データ」を要求
```
この図を見て、以下のJSONで出力して:
{
  "nodes": [...],
  "edges": [...],
  "annotations": [...]
}
```
→ 曖昧な散文ではなく構造化させることで**誤認識を検出しやすい**

### テク2: 図を2段階で
```
1. "まずこの図の大枠構造を教えて"
2. "A→Bの矢印の意味を詳しく"
```

### テク3: 説明→検証
```
私が理解している図の内容は以下の通りです:
[テキスト説明]
この理解で間違いないか、画像と突き合わせて指摘してください。
```

### テク4: 元データから再構築
```
グラフの画像だけでなく、元のExcelシートも渡して。
Devinに「数値から再計算して傾向を分析」させれば、画像の誤認識を回避できる。
```

### Devinに「図を描かせる」逆方向

入力だけでなく、**Devin → 図**の方向:

| 形式 | 方法 | 理解可能 |
|---|---|---|
| **Mermaid** | テキストで書いてMarkdownに貼る | Devin自身も読める |
| **PlantUML** | `plantuml`コマンドで画像化 | 可 |
| **matplotlib/seaborn** | Pythonで画像生成 | 可 |
| **graphviz** | DOTファイル→PNG | 可 |
| **ASCII art** | テキストで直接 | 可・読める |
| **Excel図** | `openpyxl` + `xlsxwriter` で生成 | 限定的 |
| **Word図** | `python-docx` で画像貼付 | 限定的 |

### 実践フロー（総合）

### 「Excel仕様書の中の図を読んでコードに反映したい」

```
Step 1: .xlsx をチャットに添付
Step 2: Devinに以下を依頼
  「このExcelの全シートのテキスト・表を抽出。
   加えて、埋込画像があれば xl/media を全て抽出して
   個別にVision認識し、それぞれの意味を説明してほしい」
Step 3: Devinが
  - openpyxl でセル内容展開
  - xlsx内zip展開で xl/media/*.png を取り出し
  - 画像を一つずつ Vision 解釈
Step 4: 結果を統合してコード実装方針を提案
```

### 「Word仕様書のフローチャートをMermaidに変換したい」

```
Step 1: .docx 添付
Step 2: 「3ページ目のフローチャートを抽出してMermaidで再現」
Step 3: Devinが
  - python-docx でドキュメント構造を理解
  - 該当ページ範囲を PDFに変換（unoconv / libreoffice）
  - pdf2image で画像化
  - Vision でフローチャート構造を抽出
  - Mermaid flowchart TD 形式で出力
Step 4: 人間が精度を確認し、微調整
```

### 料金・リソース面の注意

| 項目 | 考慮 |
|---|---|
| **大量ページのPDF** | 全ページ画像化するとトークン消費大 |
| **高解像度画像** | 1枚あたりのトークンも大きくなる |
| **動画からのフレーム抽出** | 枚数制限・解像度調整 |
| **Vision呼び出し回数** | ACUに影響する可能性 |

→ **必要な部分だけ切り出す**のがコスト効率もよい。

### まとめ

| ファイル/要素 | 直接理解 | Vision経由 | ベストプラクティス |
|---|---|---|---|
| **Excel 数値・表** | ⭐⭐⭐⭐⭐ | — | そのまま渡す |
| **Excel グラフ** | ⭐⭐ | ⭐⭐⭐⭐ | **PNG化して添付** |
| **Word 本文・表** | ⭐⭐⭐⭐⭐ | — | そのまま渡す |
| **Word 挿入画像** | ⭐⭐⭐（抽出後） | ⭐⭐⭐⭐ | docx unzip → media 取り出し |
| **Word フローチャート図** | ⭐⭐ | ⭐⭐⭐⭐ | **該当ページをPNGエクスポート** |
| **PDF テキスト層あり** | ⭐⭐⭐⭐⭐ | — | pdfplumber等で抽出 |
| **PDF スキャン画像** | — | ⭐⭐⭐（OCR + Vision） | Tesseract + pdf2image |
| **PDF ベクター図** | ⭐⭐ | ⭐⭐⭐⭐ | **高DPIで画像化** |
| **手書きホワイトボード** | — | ⭐⭐⭐ | 明るく鮮明な写真 + 文脈説明 |
| **複雑なCAD・回路図** | — | ⭐⭐ | 分割クロップ + 多段階質問 |

**核心**: Devinは**テキスト・表・数値は完全に理解**、**図は「画像化できれば概要〜構造レベルまで理解可」**。特にExcelのネイティブグラフやWord/PDF内のベクター図は**素のままでは不十分**で、**PNG/JPGに画像化してから渡す**のがセオリー。精度を上げたい時は **(1) 高DPI画像** + **(2) 補助説明文** + **(3) 構造化出力要求** + **(4) 分割質問** の4点セット。細かい数値ラベルや日本語手書き、超高密度な技術図は現時点でも誤認識が起きやすいため、**人間による最終確認が必須**です。
