# Q13. Devinを使う開発者はGitHubアカウント + Gitの知識・経験が必要？

📚 [トップ索引](../../README.md) ｜ [カテゴリ索引: GitHub・SCM連携](README.md)

---

> **メタ**: 最終確認日 2026/4/16 ｜ 根拠 https://docs.devin.ai/integrations/github ｜ 推定なし

### 結論: **半分Yes、半分No**


- **SCMアカウント（GitHub等）** → 実質必須
- **Gitコマンドの実操作スキル** → 不要（Devinが代行）
- **コードレビューができる力** → **必須**

### 「GitHubアカウント」は実質必須

- 個人のGitHubアカウントそのものは必須ではない（組織のGitLab等でも可）
- ただし**何らかのSCMアカウント**は必要
- 組織でGitHub Organizationに所属し、そこにリポジトリがある形が一般的

### 「Gitの知識・経験」は必須ではない（ただし"ある方が楽"）

Devinが肩代わりしてくれる領域:
- `git clone`, `git checkout -b`, `git add`, `git commit`, `git push` → 全部Devinがやる
- ブランチ名の命名、コミットメッセージ → Devinが考える
- PR作成、PR本文の記述 → Devinがやる
- マージコンフリクトの解消 → Devinが試みる（難しい場合は人間に相談）
- リベース、チェリーピック → 指示すればDevinがやる

人間側に残る作業:
- **PRを見て「これをマージしていいか」を判断**する
- GitHub上で**PRをApprove/Merge**する（人間の責任として残すべき）
- コードを読んでコメントする（Devinはコメントを拾って直す）

### 必要なスキル（最低限）

| スキル | 必要度 | なぜ必要か |
|---|---|---|
| **コードを読んで良し悪しを判断できる** | ★★★ 必須 | PRレビューが開発の質を決めるため |
| **GitHub等のPR/レビューの概念を理解** | ★★★ 必須 | DevinはPRベースで動く |
| **作りたいものを具体的に言語化できる** | ★★★ 必須 | 曖昧な指示では精度が落ちる |
| **基本的なCI/CDの概念** | ★★ 推奨 | Devinが「CIが通った」と言う内容を理解するため |
| **Gitコマンドの実操作** | ★ あれば便利 | なくてもDevinがやってくれる |
| **特定言語/FWの実装力** | ★ あれば便利 | レビュー精度が上がるが必須ではない |

### 想定ユーザーの例

1. **シニアエンジニア** — レビュー判断力が高く、Devinを自分の分身として使う
2. **テックリード** — 複数のDevinを並列運用して開発スループットを上げる
3. **プロダクトマネージャー（技術背景あり）** — 軽い改修や検証をDevinに任せる
4. **非エンジニアの企画職** — 厳しい。レビュー判断ができないと破綻する

### Devinが不向きなユーザー

- コードが読めない / PRレビューができない
- 「動けばいい」で品質判断ができない
- GitHubを触ったことがない・怖がる
- → このケースでは、まず**人間の教育**が先。Devinはスキル不足の補填にはならない

### なぜ「コードが読める」が必須なのか

Devinは**自信満々で間違える**ことがある:
- 存在しない関数を呼ぶ / 型を誤解する
- テストを無効化してCIを通す
- セキュリティ上の問題（SQLインジェクション等）を見落とす
- 「できた」と言いつつ実装が不完全

これを**検知するのは人間の役割**。マージ前にPRを読んで「これはマズい」と言える人がいないと、品質が崩壊する。

### 「GitHub知識・経験がない人」にDevinを使わせたい場合

1. まず1人のシニアがDevinを試用してノウハウ蓄積
2. チーム向けにPlaybookを整備（社内標準パターンを定型化）
3. PR/レビューの基本教育を先に実施
4. 最初はペア運用（Devin + 指導役のエンジニア）で慣れてもらう
5. 徐々に1人で使えるようにする

### まとめ

「**Gitの操作ができる人**」ではなく「**コードをレビューできる人**」が想定ユーザー。この前提を崩すと品質事故の温床になる。

**核心**: **Gitコマンド操作スキルは不要（Devinが代行）だが、「コードをレビューできる力」は必須**。SCMアカウント（GitHub等）は実質必須で、レビュー判断ができない人にDevinは向かない。
